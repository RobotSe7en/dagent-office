# 原生 DOCX 导出

`exportDocx` 从当前已校验的 HTML 文档包、样式、资源及 Word 元数据生成原生 OOXML。无需原始 DOCX；输出包含可编辑的段落、文字、样式、编号、表格、图片、字段、批注和修订，不使用 HTML 附件或 `altChunk` 代替正文。实现与导入、浏览器渲染及宿主存储分开。

```ts
import { exportDocx } from "@dagent-office/office";

const { bytes, report } = exportDocx(session);
// 宿主保存 bytes；向用户展示 report 中未能导出的批注。
// 完整协作信息仍可通过 session.serialize() 保存为 HTML 文档包。
```

输入是只读 `DocumentModel`，编辑会话也满足该接口。导出先重新打开序列化源进行完整校验，不信任调用者提供的快照。同步执行，不访问 DOM、文件系统、网络、Office 软件、宿主凭据或模型。原包和当前修订均不改变。

`DocxExportOptions` 与 ZIP 选项共用 `limits`、`maxZipBytes`。默认展开包 32 MiB、单文件 8 MiB、1024 项和共享 XML 节点预算；CSS 变量展开、匹配工作、样式继承、批注映射、表格合并的展开及输出生成另受预算约束；表格续接单元格在分配前检查预算。XML 属性与文字分别转义；XML 1.0 无法编码的字符明确失败，保留有效 UTF-16、扩展汉字及变体序列。生成文件名与关系标识由适配器分配，文档 ID 和资源路径不成为文件系统入口或授权。

## 原生内容

| 内容 | 写回方式 |
| --- | --- |
| 段落、标题与文字 | 原生段落、文字片段、换行和分页、直接格式、源字体名称及四类文字字体角色 |
| 样式 | 段落／字符／表格／编号样式、继承与关联；保留原属性归属与继承，同时纳入当前 CSS 新增的属性；直接覆盖相对实际原生基线计算 |
| 编号 | 原生多级定义及实例、格式、起始值、重启与后缀；支持编辑新增的普通 HTML 列表与原生编号并存 |
| 表格 | 网格、横纵合并、嵌套、宽度、边框、底纹、单元格边距与对齐、重复表头、行高及禁止跨页拆行 |
| 节与辅助内容 | 按源顺序写回页面尺寸、边距、分节、页码重启、首／偶／默认页眉页脚及共享故事 |
| 链接和书签 | 故事内原生书签、外部链接关系与内部目标；不访问目标 |
| 字段 | 简单／复杂／嵌套／跨段落字段、指令、锁定与脏标记、缓存结果及目录内容控件；导出不执行指令 |
| 图片 | 授权 PNG/JPEG/WebP 字节、明确的内嵌宽高与替代文字，不下载资源或字体 |
| 文字修订 | 原生插入／删除、删除内容、作者与时间；校阅颜色与装饰不固化为接受修订后的正文格式 |
| 批注 | 经典原生范围、富文本正文或文字指令、作者与时间、原生已解决状态 |

CSS 级联在独立适配器内解析，支持已有安全选择器、优先级、继承、自定义属性、常用长度和有界维度计算。它生成 Word 原生属性，不把浏览器字体替代或分页装饰保存到 DOCX。源中的 Word 字体名称继续保留；实际字体选择由打开文件的应用决定。

HTML/CSS 的能力范围比当前原生 Word 映射更广。无法表达的正文格式明确抛出 `UnsupportedFeature`，不返回部分正文。例如透明文字／半透明颜色、独立单词间距、任意字重、上下限尺寸、普通元素固定尺寸或内边距、非折叠表格、段落禁止换行、行内边框、单元格独立高度、反向列表及无法合并为单一原生格式的多层装饰。原生字号以半磅、常规尺寸以缇量化，浏览器和 Office 的字形、行距及边框冲突不保证逐像素相同。字段缓存原样写出，Office 自己更新字段后可以改变显示值。普通 HTML 的折叠空白须已规范化；需要逐字保留多个空格、制表或换行时使用 `white-space:pre-wrap`，不能把浏览器折叠后的外观与未折叠的源偏移混为一谈。

## 批注报告

`report` 绑定导出的文档 ID 和修订，包含 `exportedAnnotationIds` 与 `unexportedAnnotations`。文字范围按实际源叶节点和 UTF-16 偏移切分，段落末尾不会移到下一段；连续范围可以组成一个原生范围。不猜测矩形坐标对应的文字，也不扩大不连续范围。

按已确定的产品策略，空白矩形、`needs_reanchor`、跨内容域、不连续及其他不能精确绑定的批注列入报告，正文继续导出。每项给出批注 ID 和原因；完整批注、矩形与协作状态仍保留在 HTML 包中。调用者应展示报告，不能仅把下载成功当作批注已全部写入。

已解决状态通过 `commentsExtended.xml` 的 `w15:commentEx/@w15:done` 写回，并用批注最后一段的 `w14:paraId` 关联。读取器接受这一状态扩展，检查唯一映射及布尔值；线程父级、回复和其他现代线程部件继续明确拒绝。依据：[Microsoft CommentEx](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.office2013.word.commentex?view=openxml-3.0.1)。

## 验证

工程测试涵盖独立样例及另一生产者的输入、读取回归、编辑后导出、样式继承、字段控制、批注范围与状态、预算和确定性。实际 Office 重开使用本机及 CI 的 LibreOffice、Poppler 与明确安装的 Noto／Liberation 字体：

```bash
pnpm build:packages
node scripts/docx-export-acceptance.mjs
```

脚本覆盖 18 份独立／生产者样例及一份正文修改、批注解决、容器／单元格行内格式编辑后的文件，导出、实际打开并重存、重新导入，再核对可编辑正文、字段行为、修订、批注状态、资源数量及 PDF 页数／图片。导出后的原生指令先与源逐项核对；LibreOffice 自己会改写嵌套 IF 字段和部分目录开关，实际重存以原文件经同一应用重存的结果独立对照，不能把应用的改写误记为指令无损。结果和渲染图保存于 `.cache/docx-export-acceptance`，记录工具版本、字体和输入／输出摘要。[阶段验收记录](../examples/docx/export-reference.json) 保存本次工具／字体、19 份样例的摘要和结果；人工已对照正文编号、表格合并、图片、样式及页眉页脚、修订的固定字体渲染。原文件隐式的图片间隔未进入既有 HTML 源，导出采用该源的间隔，不猜回原应用默认值。

当前合并基线为 LibreOffice。Word、WPS 尚未实机验证，不能把 LibreOffice 通过写成二者通过。不提供全 OOXML XSD 认证，也不宣称与任意 Office 应用逐像素一致。普通 JavaScript、React、Node 打包消费及完整 Playground 往返在 R1-14 验收。
