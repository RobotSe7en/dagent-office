# 达智集成

达智通过 npm 包接入编辑器，通过有版本的本机协议调用 TypeScript 转换代码。Enterprise 继续管理身份、权限、模型执行、工作区和审计；SDK 不依赖 `server.*` 或 `dagent`。

本文是接入设计，尚未实施。独立 HTML/Word 闭环已完成；按用户决定延后 R1-15 达智最小智能体验证，当前先进入[第二轮 PPT](iteration-2.md)，恢复时间另行安排，保留原任务编号及未完成的宿主验收项。第四轮完善私有会话、草稿、正式存储和部署。达智为首个宿主，公开 SDK 中不包含其账号、项目、路由或工作区类型。

| 现有位置 | 计划中的接入 |

| `web/src/features/artifacts/artifactPreview.ts` | 复用产物选择与预览容器，增加独立编辑入口及组件生命周期管理 |
| `server/documents/` | 第一轮适配 Node 字节转换协议；第四轮完善文档会话与正式转换调度 |

现有预览及下载 API 保持兼容。编辑器能力通过新增配置或入口接入，不重新定义已有字段含义。实际修改前阅读 Enterprise 的前端样式、产品和兼容性契约。

## 第一轮最小接入

前置条件是独立 Playground 已通过 HTML/DOCX 输入、富文本、中文输入法、分页、批注、固定提案、DOCX/PDF 导出和重开。达智接入不承担替代 SDK 独立验收的职责。

1. 在现有预览区域增加薄包装组件，挂载相同工作台，加载已授权 DOCX 或 HTML 文档包；不从只读 PDF 反推编辑结构。
2. 将统一提交事件产生的 `DocumentInteractionRequest` 作为结构化附件交给既有智能体消息入口。整体要求、模型配置、凭据和执行状态沿用现有产品。
3. 智能体按请求中的支持操作输出 `EditProposal` JSON 产物。宿主保留原请求，按当前主体和任务授权读取用户选定的结果。
4. 以请求 ID、文档 ID 和基准修订关联结果，回传文档组件；核心生成候选，用户查看并应用。
5. 验证整批撤销、DOCX/PDF 导出及重开；Node 转换由 Python 适配相同的有版本字节协议。

第一轮不新增独立 LLM 接口、模型代理、文档内 AI 弹窗、持久化表或正式工作区文件保存路径。先通过下载新结果完成演示，保留现有历史文件读取语义。独立 Playground 通过固定提案验证文档侧链路，不提供模型服务。

智能体产出的提案文件遵循既有 Run 产物和工作区提交规则。这可能产生正常的 Run 输出版本，但不表示浏览器文档已接受提案或来源 Office 文件已保存。提案产物、会话提交和正式文件提交分别反馈。

## 会话与保存

文档会话记录来源文件的不可变引用、所有者、当前草稿版本和目标工作区信息。SDK 的 `revision` 标识草稿内容变化，Workspace head 标识平台正式文件快照，两者承担不同职责。

```text
授权读取历史产物或当前文件
    → 创建当前主体的私有编辑会话
    → 导入 HTML 文档包
    → 保存草稿、批注及模型提案
    → 应用提案更新草稿
    → 用户保存文件
    → 导出候选 Office 文件
    → 复核权限、expected head 和分支写入排他
    → 原子形成新工作区版本
```

历史 Run 产物保持不可变。编辑历史产物默认另存为新文件；当前目标分支的 head 在选择保存目标时确定，不能把历史来源 head 当作当前目标版本。覆盖工作区已有路径时，同样要比较目标当前 head。

保存草稿和保存正式文件分别反馈。浏览器提交成功、Node 导出成功和 Workspace 提交成功是不同结果，前两者不能触发正式保存成功提示。正式提交失败保留私有草稿及候选结果，允许用户查看实际原因，不猜测已经提交。

独立 Conversation 当前的文件路径按 Enterprise 契约只读。实现本能力时新增当前 owner 的私有分支写入合同与接口，历史读取 API 继续只读；同步更新契约和回归测试，不通过开启预览组件的 edit 开关绕过后端。

## 项目文件

个人项目工作区的编辑遵循当前主体的 `execute` 权限和私有分支规则。文档保存进入该主体的私有工作区；公开到项目材料仍是单独的 `publish_files` 动作。

项目成员或项目管理员不能因此读取另一个成员的未公开会话、产物、批注或草稿。撤销权限及禁用账号后，后续文件、资源和提交请求重新鉴权。

模型调用或另一个写入动作持有分支写入权时，正式文件提交遵循现有冲突语义。网页允许保留会话草稿，不使用第二条写入路径覆盖正在执行的工作区。

## 数据与模型边界

- 每次读取文档、资源、批注、候选预览及正式提交，都验证当前主体和文档会话所有权。
- 请求 ID、document ID、路径、资源 hash、提案 ID 和前端只读开关都不构成授权。
- 缓存由宿主提供主体隔离的命名空间，并绑定文档版本、转换器和字体环境。身份切换时释放旧文档、缓存引用和模型上下文。
- 模型只得到本次授权提供的文档内容。若需要知识库内容，继续经 Enterprise 的权限和检索入口，以请求范围与主体可读范围的交集取数。
- Node 转换进程接收授权字节及受控资源，不持有 Enterprise 数据库、其他用户路径或模型凭据。

SDK 的公开类型只包含文档、操作和交互概念，以上规则在 Enterprise 适配层实施。其他宿主通过提交回调、提案回传、资源和存储接口接入自己的智能体，SDK 不读取它们的数据库或凭据。

## 宿主智能体运行

SDK 输出文档快照的相关区块、批注、样式、资源描述和支持操作 Schema。宿主将这些数据接入既有对话、附件或工具，组织提示词、模型上下文、token 预算及取消；文档组件只处理请求交接和提案回传。

第一轮采用请求附件和提案 JSON 产物；后续确需 Agent 工具时，使用“读取文档、读取批注、提出修改”的中性语义，复用 `dagent-ai` 公共注册、校验和运行能力。工具只产生提案，不绕过文档事务或新增直接保存源文件的通道。

核心校验提案并预览，用户接受后更新会话。普通 Run 产物继续按其既有机制提交，正式 Office 保存另行检查目标 head、权限和写入排他。Run、Review、取消、工具装载和凭据语义继续归宿主及既有智能体 SDK。

身份或文件切换时释放旧会话的 UI 和上下文引用。外部 Run 的取消由宿主管理；迟到提案仍检查当前会话、请求和修订，不能写入另一文档，也不能把任务取消当作批注已完成。

## Node 进程和持久化

首版将 Node 入口作为受管理的本机转换子进程，不新增独立的公网服务。请求包含精确协议版本、任务 ID、格式、授权输入及输出选项；返回结构化结果、资源清单或类型明确的错误。

Python 使用 Pydantic 校验请求和结果，限制输入、输出、并发、超时及子进程生命周期。Chromium 只访问该转换任务的文档和授权资源。部署镜像随平台一起固定 Node、Chromium、字体和 SDK 版本。

草稿及批注需要持久化时使用有版本的文档包及受控会话记录，纳入备份和删除生命周期。若新增数据库表，递增 Enterprise schema，提供顺序、原子、只升级迁移；当前 fresh schema 同步更新。不可变历史不原地重写，升级按现有兼容性契约执行。

## 必须通过的集成用例

第一轮先验证下列用例中的授权输入、请求/结果关联、会话隔离与不可变来源；涉及持久草稿和正式保存的用例在第四轮随相应接口落地。

1. 用户甲不能读取、导出或提交用户乙的文档、资源、批注和提案；项目管理员也不能越过私有内容边界。
2. 同一主体权限被撤销后，已有会话和资源引用不能继续授权读写。
3. 历史产物编辑产生新结果，原 Run 的文件及快照不变。
4. 目标 head 改变或分支正被写入时，提交失败且无部分文件或 head 更新。
5. 草稿成功、导出成功和正式提交失败能明确区分；失败后仍能查看自己的草稿。
6. 用户切换后不复用旧身份的预览、缓存、文档上下文和模型提案。
7. 统一提交使用既有智能体消息链路；任务失败、取消或输出非法提案时，当前文档和批注保持。
8. 请求 ID、文档或修订错配以及旧会话迟到结果被拒绝；原请求和提案仍可按宿主权限查看。

以上用例与实际新增接口一同落地，不扩展其他平台资源的共享权限。
