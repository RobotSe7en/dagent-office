# 整体实施计划

按五个可演示、可验收的迭代交付。第一轮合并 HTML 协作基础与 Word 完整闭环：先在独立 Playground 完成文档读写、人工编辑、批注、提案和 DOCX/PDF 导出重开，再接入达智现有智能体验证。随后依次覆盖 PPT、Excel、正式宿主存储与发布准备。

当前已完成工程与包基础、三格式模型设计、声明范围内的 DOCX 读取/只读验收、[R1-06/R1-07 核心事务与锚点映射](document-session.md)及 [R1-08 预览与交互](preview-interaction.md)，下一步 R1-09 工作台与协议闭环。本文其余内容是路线设计，不代表能力已经实现。[总体架构](architecture.md)定义模块和宿主边界，[第一轮实施细则](iteration-1.md)定义首轮任务、依赖及验收。排期按每轮实际样本收敛，不用代码生成速度替代兼容性验收。

## 交付原则

- SDK 提供可嵌入工作台和底层 API；宿主复用自己的页面、智能体、身份和存储。
- 四个库模块为 `core`、`editor`、`office`、`node`，不建设独立模型调用包或智能体运行时。
- 独立 Playground 先验证公开 API 和完整 Word 链路；达智再验证真实智能体交互。两者使用相同组件和提案协议。
- 每轮以可演示链路、声明能力及验收结果为退出条件。技术验证、已实现能力和后续计划分别记录。

## 迭代 1：HTML 与 Word 完整协作

### 阶段 A：模型、DOCX 读取与只读验收

R1-02 至 R1-05 已完成工程、契约、只读文档包和资源/ZIP。随后先完成 R1-05A 的[三格式数据模型设计](data-model.md)，明确 Word、PPT、Excel 的类型、引用及唯一持久化来源；当前实现 Word 部分。

将 R1-10 移到 R1-06 前，完成 DOCX 的 OPC/XML、正文、样式继承、主题、编号、表格、图片、节和页眉页脚映射，并覆盖链接、制表位、字段、原生批注及文字插入/删除修订。字段保留语义和缓存；修订保留作者时间及删除内容。未支持内容或版式明确失败，不默认部分导入。

独立 Playground 提供最小只读预览，使用八类功能 DOCX、额外中文字体样例及其独立生产者版本验证结构、样式、资源、文档包保存重开和固定字体渲染。LibreOffice 自动参考基线先放行，Word/WPS 兼容性另记。读取验收通过后才开始 R1-06。

### 阶段 B：事务、交互与独立 Word 文件闭环

按 R1-06 至 R1-09 实现操作、候选、历史、锚点、批注及工作台，复用阶段 A 的只读渲染。人工与模型修改通过同一事务边界，使用导入 DOCX 测试未修改内容及样式保留，HTML 小样例用于精确边界测试。

接入 Tiptap，验证中文输入、跨段落选择、表格输入和统一历史，保留字段、批注及修订语义。再增加派生分页，正文源不按自动分页拆分；实现支持的页码、总页数和目录更新。

从当前文档源导出原生 DOCX，覆盖已支持的导入语义。Node/Chromium 提供固定字体渲染及 PDF。检查文字、表格和图片仍可编辑，Word/WPS 打开无需修复，重新导入核对内容及样式。Playground 使用固定提案完成独立闭环，开发转换进程不开放公网服务或引入模型代理。

### 阶段 C：达智智能体验证

阶段 B 通过后，达智在现有预览容器挂载同一工作台，加载授权 DOCX 或文档包。请求由现有消息与附件链路交给宿主智能体，智能体产生提案 JSON 产物，再由宿主选择并回传文档组件。

验证两处以上批注统一修改、差异、整批应用、撤销、DOCX/PDF 导出及旧修订拒绝。首轮可下载新结果，不新增正式工作区保存路径、独立 LLM 接口或持久化表。提案产物、会话提交和正式文件保存分别反馈。

### 验证与依赖收敛

Tiptap、DOCX、PDF 在第一轮从早期验证发展为正式支持能力。PPT 原生对象输出、XLSX 读写及公式引擎桥接保留为提前验证；记录实际版本及许可后锁定依赖。

至少准备 18 份合成格式样例，Word 8 份，PPT 和 Excel 各 5 份，覆盖中文、表格、图片、样式继承、分页或几何及公式。Word 样例进入首轮全链路验收，PPT/Excel 样例仅标记为技术验证。真实用户文档保留在私有目录，不能提交或发送给未授权服务。

完整支持范围、任务依赖、技术验证和演示脚本见[第一轮实施细则](iteration-1.md)。

## 迭代 2：PPT 编辑

先实现幻灯片、文本框、图片、基本形状、表格和组，再扩展支持的图表。母版、布局和主题保留引用，同时计算预览需要的有效样式。

建立逻辑坐标与显示缩放转换，拖拽和提案布局使用同一几何操作。文字选区与对象选区分别处理，支持多个对象统一批注，例如“对齐并简化这组内容”。

自行实现 PPTX OOXML 的原生对象输出及 HTML 对象映射，ZIP/XML 等通用能力复用成熟基础库。检查原生文本及表格结构，在参考渲染器中检查溢出、错位、层级、背景和字体。

## 迭代 3：Excel 编辑

从值、类型、公式、数字格式、行列尺寸、合并和跨表引用开始，实现区域选择、批量编辑、公式计算器及依赖更新。原始公式缓存与编辑后的实际计算状态分别表示。

自行实现 XLSX OOXML 读写，计算适配器负责公式求值与依赖。验证 Univer 基础计算能力，持久化仍服从 HTML 文档源，不保存另一套可独立变化的工作簿 JSON。命名范围、条件格式和图表按矩阵补齐。

固定资源预算测量打开、首屏交互、修改计算、内存和 DOM 数量。完整数据量增长时，DOM 数量应受可视窗口约束；实际支持上限由测量写入能力说明。

## 迭代 4：正式宿主集成

按[达智集成](dagent-integration.md)实现前后端存储和部署接口。保留第一轮智能体交互边界，扩展正式会话、草稿、资源、宿主版本与 Node 转换调度。

历史 Run 产物先创建私有会话。保存时生成新文件或工作区版本，检查主体权限、目标 expected head 及分支写入排他；共享项目发布仍是独立授权动作。异步保存只确认被保存的快照，之后编辑仍未保存。

新增持久化数据和接口时同步 Enterprise 产品与兼容性契约。引入数据库表则提供版本递增、顺序升级、原子迁移及支持基线测试。复用既有 `dagent-ai` 公共注册、校验和运行机制，不复制 Runner。

## 迭代 5：兼容性与发布准备

针对声明支持的特性扩充实际文档和能力矩阵，明确哪些原生可编辑、哪些对象视觉保留、哪些无法转换。不能静默丢弃内容，也不能以整页栅格化代替可编辑导出。

宿主可以显式发起智能体辅助布局修正，由宿主管理预算并返回提案。检查文字、数值和公式不因视觉修正改变，复杂装饰仅按单对象视觉保留。

完成浏览器卸载、Worker 取消、资源 URL 释放、转换子进程清理、迟到结果及身份切换验证。普通 JavaScript、React、Node、独立演示和达智均消费打包产物，不通过源码路径绕过边界。

## 能力、兼容性和发布门槛

能力矩阵分别记录导入、预览、人工编辑、智能体修改、导出和重开。导入视觉对照来源文件，导出视觉对照修改后的文档。Word、PPT、Excel 的文字、表格、单元格和公式按原生语义输出。

WPS 生成的 DOCX、PPTX、XLSX 走相同路径；旧式 `.wps`、`.et`、`.dps` 通过可选转换器导入，首版统一输出 OOXML。适配器报告无法转换项，不隐式降级。

发布前确定第一方许可证、依赖与字体许可并记录实际锁定版本。文档格式和交互协议首次发布前冻结；已发布文档读取器按版本保留，未知版本拒绝且不改原字节，历史修订不原地重写。

性能及生命周期限额由样例测量收敛，记录输入规模、打开、首屏、修改、计算、内存和 DOM。视觉基线固定字体、视口、转换器及渲染环境。发布说明区分已支持、视觉保留和暂不支持。

## 回归检查

| 类别 | 验证内容 |
| --- | --- |
| 核心事务 | 完整成功、部分失败不变、无变化、撤销重做、旧候选及旧提案拒绝 |
| 交互与批注 | 请求关联、多批注提交、完整上下文、跨节点、空白区域、锚点映射及提案状态 |
| 人工编辑 | 中文输入法、跨段落、表格输入、选区、样式、粘贴和统一历史 |
| 内容和结构 | 文字、数字、公式、表格、图片、对象和引用保留 |
| 视觉 | 固定字体及视口截图、溢出、遮挡、分页和几何 |
| 可编辑性 | 原生文字、表格、形状、单元格公式；导出重开无需修复 |
| 宿主边界 | 所有权、权限撤销、资源访问、身份切换、并发写入和旧 head |
| 性能与生命周期 | 大表长文档、取消卸载、资源回收、迟到结果和有界转换 |
| 包与契约 | 公开入口、类型及 Schema 一致、JS/React/Node 打包消费、无宿主业务依赖 |

多人实时协同、完整宏和数百种函数兼容不作为 0.1 前置条件。后续按真实文档与工作流扩展，并保持同一事务和格式边界。
