## 目标与已定决策

交付以下独立链路：

```text
新建或打开 PPTX → 编排幻灯片 → 编辑对象、文字、表格与图表
    → 修改主题、母版和布局 → 编辑演讲者备注与批注
    → 固定提案审阅、应用、撤销与重做
    → 导出 PPTX/PDF/PNG 和文档包 → 外部打开、编辑与重新导入
```

已由用户确定的决策：

- 延后达智接入，保留 R1-15；Word 为“独立闭环完成，宿主验证待做”，不把 R1-16 标为全部通过。
- 交付常用 PPT 编辑闭环，包含新建文稿、幻灯片编排及对象增删，不限于修改已有文件。
- 遵循 DOCX 技术路线，自行实现输入适配、对象编辑、版式映射及 OOXML 读写。继续复用现有 ZIP、XML、HTML/CSS、哈希和浏览器基础能力。
- 不引入第三方富文本编辑器、幻灯片编辑器、图表编辑器或 Office 转换库。形状、图表的显示适配同样由本项目实现。
- 本轮提供主题、母版及布局的编辑界面，验证对引用页面的整体影响。
- 演讲者备注可编辑，经典和现代原生批注均进入读取、编辑与导出范围。
- 基础柱状图、折线图、饼图支持数据编辑与原生导出。数据范围为图表内置常量表，公式计算和外部 Excel 联动延后。
- 外部打开和视觉参考沿用 LibreOffice；PowerPoint、WPS 单列实际验证结果，不将未验证记录成通过。
- 新建文稿默认现代批注，导入文件默认保留来源格式；提供经典兼容导出并明确报告无法表达的信息。
- SDK、Playground 继续通过固定提案验证协作链路；真实模型执行与正式宿主存储沿用宿主边界。

以下是本轮验收目标；实施中按读取、源保留、预览、人工编辑、提案修改、导出及重开分别记录结果。

| 外观 | 实色、透明度、线性渐变、轮廓、虚线、基础外阴影 | 复杂效果、纹理、三维和未支持的填充明确失败 |

| 图片 | 授权 PNG/JPEG/WebP、尺寸、矩形裁剪、旋转、翻转、替代文字及原始字节保留 | SVG/EMF/WMF 等图片容器和复杂图片效果延后；派生形状 SVG 不等于开放任意 SVG 输入 |
| 表格 | DrawingML 原生表格、行列增删、尺寸、合并拆分、文字、填充、边框、对齐 | 不以 HTML 截图替代原生表格；嵌套表格延后 |
| 主题 | 主题颜色、拉丁／东亚／复杂文字字体角色及默认样式引用 | 外观值保存在 CSS，元数据保留角色与继承；不复制一份可独立编辑的颜色或字体值 |
| 母版与布局 | 新增、复制、改名、内容编辑、引用调整及安全删除 | 专门编辑模式修改定义；普通页面不直接编辑继承装饰 |
| 占位符 | 类型及身份匹配、几何和文字样式继承、局部覆盖；页脚、页码及支持的日期字段 | 日期保留来源缓存；不以当前系统时间静默更新；页码按当前顺序派生 |
| 图表 | 二维簇状柱状图、普通折线图、单系列饼图；分类、系列、数值、标题、图例、轴及基础标签 | 堆积、组合、三维、散点、次坐标轴及其他复杂图表延后 |
| 图表数据 | 常量数据集及普通本地范围引用；原生图表缓存和内嵌 XLSX 同步生成 | 不执行工作表单元格公式，不读取外部连接；最小 XLSX 适配不成为第三轮完整 Excel 实现 |
| 备注 | 逐页富文本备注读取、展示、编辑、原生写回，保留支持的备注母版 | 备注与幻灯片正文为不同内容域；备注页打印排版编辑延后 |
| 经典批注 | 正文、作者、时间、幻灯片位置的导入、编辑、删除及原生导出 | 经典格式不能表达的线程、状态及精确锚点进入导出报告 |
| 现代批注 | 富文本正文、回复线程、作者与时间、解决状态、幻灯片／对象／文字锚点 | 任务分配、云通知、提及交互及其他未定义扩展延后 |
| 协作 | 多批注请求、冻结上下文、固定提案、内容／几何／数据差异、整批应用、拒绝、撤销重做 | 普通和全局作用域分别校验；真实模型执行归宿主 |
| 输出 | HTML 包、原生可编辑 PPTX、逐页 PDF、指定幻灯片 PNG | PDF/PNG 默认只含幻灯片画布，不含批注面板和备注 |

新建文稿使用一页空白幻灯片，以及空白、标题、标题与正文三种基础布局。编辑会话至少保留一页，删除最后一页明确失败。隐藏页在编辑界面保留标记，默认 PDF 按文稿顺序包含全部页；PNG 按明确的页面索引输出。

SmartArt、音视频、动画、切换效果、三维对象、任意自由曲线、嵌入 OLE、宏及加密文稿延后。遇到超出支持矩阵的内容返回有界、可定位的错误，不默认返回部分文稿。允许忽略的纯 UI／缓存信息须有明确规则和用例，不能把未知可见内容当作无关信息。

## 数据来源、模块与接口

### 唯一文档源

版本化 HTML 文档包继续是唯一持久化来源，不保存独立可写的 PPT AST、编辑器状态或来源 PPTX 回写副本。

- 幻灯片、对象、文字、表格、备注和富文本批注正文保存在具有稳定身份的 HTML 节点中。
- 幻灯片顺序和对象层级以对应源节点顺序为准。元数据登记身份及引用，其数组顺序不构成第二份编排来源。
- 对象局部坐标、尺寸、旋转、翻转和组坐标保存在类型化 data-office-* 属性中，逻辑单位为 pt。连接线允许单轴零尺寸；二维区域和可逆组变换按类型校验。
- CSS 保存外观，元数据保存主题、母版、布局角色及继承引用；定位 CSS、实例 DOM、合成矩阵、测量值和 SVG 均为派生结果。
- 图表数据集在类型化元数据中唯一保存，图表按身份引用；显示 SVG、内嵌 XLSX 和图表缓存均由当前数据派生。
- 图表内嵌工作簿只接受支持的常量表及图表范围。未支持的公式、外部连接或无法保留的工作簿内容明确失败。缓存与常量来源不一致时明确诊断，不将旧缓存冒充最新数据。
- 母版、布局、备注和批注正文有明确的内容根和投影关系，预览组合不复制为另一套可修改的幻灯片源。

[PPT 元数据设计示例](data-model.md#ppt-元数据设计示例)是既有设计输入，不是当前契约已接受的包。R2-02 落地严格结构及完整可校验样例，保留 geometry 在 HTML、外观在 CSS、引用在元数据的边界。

### 模块职责与公开接口

| 模块 | 实现职责与接口变化 |
| --- | --- |
| core | Presentation 契约、JSON Schema、语义校验、新建文稿、格式操作、批注回复、影响范围及统一历史 |
| office | importPptx、exportPptx；复用 OPC/XML/ZIP 基础，自行实现 PresentationML、DrawingML 和图表数据的最小 XLSX 映射 |
| render | 固定幻灯片画布、继承实例投影、形状与图表 SVG、字体和溢出诊断、PPT 渲染报告 |
| editor | 现有工作台按格式接入 PPT 适配器，复用批注、差异、事务及自研原生输入基础 |
| node | 相同转换器接收 PPT 文档包／PPTX，生成 PDF/PNG，保留隔离任务和有界字节协议 |
| Playground | PPT 入口、对象及母版编辑工具、备注、图表数据面板、固定提案、下载与导出报告；只使用公开包入口 |

公开入口的目标职责如下，完整类型随对应实现交付，不提前发布占位 API：

```ts
// core：创建已校验的初始 HTML 文档包。
createPresentation(options): DocumentPackage

// office：授权字节进入同一文档模型；无网络、文件系统或模型调用。
importPptx(bytes, options): DocumentPackage

// office：从当前文档源编译原生 PPTX，返回字节和完整导出报告。
exportPptx(model, options?): PptxExportResult
```

- 新建与导入要求宿主提供 documentId。导入沿用 ZIP 选项与读取预算，生成修订 0。
- 导出报告绑定 documentId/revision，列出已导出的批注以及无法表达的正文以外协作信息。无法表达的正文或对象格式直接失败，不生成缺失正文的文件。
- 批注格式选项为 preserve、modern、classic。默认 preserve，导入保留来源格式，新建使用现代格式；兼容导出的线程、状态、锚点损失逐项报告。
- 保留 openDocument、snapshot、getNode、serialize、会话及挂载入口，通过明确的格式分派扩展；PPT 渲染报告表达幻灯片，不伪造 Word 节、页眉页脚或自动分页。
- Word 严格契约与旧包读取行为继续保留。版本号沿用当前未发布的格式／交互版本 1 草案，新增能力显式定义，workbook 继续明确拒绝。
- 新操作仅向当前格式和作用域开放，不能因扩大公共枚举而把 PPT 操作自动暴露给 Word 请求。
- 依赖边界检查覆盖第三方编辑器及格式转换库。规范、依赖和验收工具记录来源、版本及许可，不复制 ibisOffice 代码。

### 统一事务与资源

幻灯片管理、对象创建与组合、几何、主题／布局、图表数据及批注回复均采用明确的类型化操作。人工输入与提案都经过 prepare → commit，整批校验成功后产生一次新修订和一次撤销记录。

1. 准备阶段检查协议、文档、修订、基准身份、操作与资源预算，在隔离候选中执行。
2. 图片新增所需的授权字节随候选准备输入，校验摘要和预算后与资源清单、对象一起提交。失败不留下孤立资源或半完成的对象。
3. 拖拽、缩放和旋转过程仅更新临时视图，结束手势后提交一次；取消、校验失败或修订冲突恢复有效源。
4. 几何只更新源变换属性，不能通过 setStyle 建立第二套坐标；层级操作更新源节点顺序。
5. 移动、换序、组合保留已有身份；复制分配新身份并重写内部引用。图片共享不可变字节，图表复制默认生成独立数据集。
6. 组变换按局部坐标组合。取消组合或重设父级无法精确表达为原生变换时失败，不近似引入斜切或奇异矩阵。
7. 主题和母版修改计算所有引用页面，在同一候选中展示并支持整体撤销；删除仍被引用的定义，必须在同批提供有效替代引用。
8. 新节点由核心分配身份，不引入同批猜测新 ID 的协议。原子创建操作包含所需子内容和格式描述。

备注、表格和文字对象继续使用自研 beforeinput、组合输入事件和 DOM Range。可替换输入适配器保留 UTF-16、源字体角色、节点身份和统一历史，不独立维护可推进文档的编辑器数据模型。编辑范围限制到对应正文、单元格、备注或批注内容域。

### 请求、差异与批注

- 普通 PPT 请求提供完整幻灯片编辑区块，以及解释这些区块所需的只读主题、母版和布局依赖。可编辑区块与只读依赖在契约中区分，不能因依赖出现在上下文里而取得修改权限。
- 全局主题／母版提案必须显式请求全局范围，冻结所有受影响页面；超预算明确失败，不截断影响面或静默丢页。
- 校验同时检查直接目标和间接影响。共享数据集、布局及主题的修改不能越过请求范围；新资源仍限于请求已经授权提供的资源描述。
- 候选差异展示内容、几何、层级、图表数据、备注、母版和受影响页。提案内容及可解决批注仍一次提交、一次撤销。
- 节点和文字锚点随稳定身份映射；目标删除或无法精确映射时保留恢复数据并进入 needs_reanchor。
- 区域绑定稳定的幻灯片身份；换序不改变归属，相关几何、字体、尺寸及布局变化时按明确规则失效。无关页面变化不使全部区域失效。
- 批注回复有严格身份、作者／时间及正文结构，和线程状态一起进入事务。来源作者仅为显示信息，不成为宿主权限。
- 原生格式无法表达的回复、解决状态或锚点逐项进入导出报告，完整信息通过 HTML 包保存；不能将下载成功提示成所有协作信息均已写回。

### 必须通过的场景

| 类别 | 验收要求 |

现代批注分别记录规范结构检查、SDK 精确重开及实际外部应用结果。LibreOffice 对正文的打开或重存不替代 PowerPoint 现代线程验证，不能将外部应用未保留的线程误记为无损通过。PowerPoint/WPS 未实机验证时明确标记未验证。

图表内嵌 XLSX 的展开、XML、数据点和生成物共用累计预算，不允许通过嵌套包重置额度。默认沿用现有文档、事务、历史及渲染限制：压缩输入 64 MiB、展开包 32 MiB、单文件 8 MiB、1024 项，以及既有节点、深度和 CSS 预算；新增展开工作量在分配前检查。限额不等于经过测量的大文稿性能承诺。

视觉验收使用固定字体、1280 × 800 视口及记录的渲染环境。浏览器截图回归沿用 maxDiffPixelRatio = 0.005、threshold = 0.2。外部参考对照核验内容、字体、位置、层级、溢出和已知版式差异，不要求跨渲染器逐像素一致。导入对照来源，导出对照当前修改后的文档源。

## 阶段交付流程

用户已授权逐阶段完成第二轮、提交推送、独立审查修复复核、创建 PR 并在 CI 全绿后自动合并。阶段 A 与 R2-07 已合并；余下按“R2-08 至 R2-13 编辑闭环”和“R2-14 至 R2-16 导出与验收”两个 PR 交付。每份交付写明实际通过的门槛，不能以单项检查代替整个阶段的验收。

每项实现完成后运行相应检查；按上述两个交付批次在工作分支统一提交推送，再单独对基准差异做审查，修复并复核后创建 PR。确认 PR 当前提交对应的全部 CI 检查通过后合并，再基于最新主分支继续后续任务。现有阶段依赖和 R2-06 门槛持续生效，不直接向 main 提交或发布 npm 包。
