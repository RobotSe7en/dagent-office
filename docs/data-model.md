# 三格式数据模型

本文定义 V1 数据模型及其扩展边界。Word、PPT、Excel 共用身份、资源、样式引用和协作协议，分别保持流式文档、定位对象和工作簿语义。模型设计不代表三种格式均已实现；Word 独立闭环已完成，R1-15 宿主验证延期；当前执行顺序见[第二轮 PPT 细则](iteration-2.md#任务分解与阶段门槛)，第一轮历史依赖见[第一轮细则](iteration-1.md#任务分解与依赖)。

## 权威来源和运行时

| 层 | 责任 | 保存规则 |
| --- | --- | --- |
| `DocumentPackage` | 版本清单、HTML、CSS、元数据、资源、批注 | 唯一持久化源；包内文件不能存在可独立修改的重复内容 |
| `DocumentModel` | 只读节点、快照、类型化格式语义、索引及引用校验 | 从包构建；通过同一源序列化；第三方 AST 不公开 |
| `DocumentEditingSession` / `DocumentSession` | 已实现事务、修订、历史及精确锚点映射；协作接口继续扩展 | 从文档模型建立；所有人工和提案编辑经过统一事务 |
| 格式中间结构 | OPC 关系、XML 树、格式转换上下文 | 仅存在于导入/导出过程；不作为第二份文档保存 |
| 渲染与计算 | DOM、有效样式、分页、几何、公式结果 | 派生状态；不得直接写成另一份权威文档 |

文字和内容顺序保存在 HTML，外观声明保存在 CSS。元数据保存 CSS 无法完整表达的格式语义、定义及引用，例如编号模式、节设置、样式关联和字段指令；不能再保存一份可独立修改的正文或颜色。资源描述引用不可变字节，来源 Office 文件不参与后续文档源的局部回写。

## 公共基座

- 文档由 `documentId/kind/formatVersion/revision` 标识；节点、样式、资源、批注分别有稳定的不透明身份。身份只用于关联，不授予访问权限。
- 节点保存类型、父子关系和语义引用；文字偏移使用 UTF-16，换行是 `\n`，内嵌图片是 U+FFFC。编号标记和自动页码不混入可编辑正文文字。
- 文本由区块与行内节点组成，保留语言、文字方向、字符格式和原生语义。人工编辑命令的覆盖范围不限制安全源样式的保留范围。
- 样式引用连接 CSS 类、原生样式身份、继承及直接覆盖。CSS 是外观值来源；主题角色和继承边保存引用。有效样式由适配器派生，不成为另一套可写属性。
- 逻辑几何以 pt 表示；对象坐标允许格式所需的负值，不复用只允许非负数的选区矩形。原生单元格列宽等特殊度量保留原生值和单位。
- 锚点、批注和历史共用[交互协议](editing-protocol.md)。来源作者是显示信息，不能作为宿主用户身份或权限。
- 每种格式声明导入、源保留、预览、编辑、导出及重开能力。未知或不能表达的语义明确失败；安全禁止项与尚未实现的普通样式分开报告。

## Word：流式文档

### 内容、内容域和节

正文、页眉、页脚及富文本批注正文是有类型的内容域。第一轮继续使用单 HTML 入口：文档根内的容器由 `data-office-story` 标记，元数据引用其根节点。正文域内按节组织连续内容；辅助内容域不参与正文选区和正文自动分页。

段落包含文字片段、换行、图片、书签标记、超链接、制表位、字段及修订容器；表格包含行、单元格、嵌套内容和合并关系。普通文字只有一份 HTML 源。页宽、页边距及分节类型以节元数据为准，预览容器尺寸由元数据生成。

节引用根节点、页面设置、首/奇偶/默认页眉页脚内容域及继承规则。明确分页保存在节点语义中；自动分页不分割正文源。表格保留网格、横纵合并、宽度、边框、内边距、底纹及对齐；图片保留资源、尺寸、替代文字及支持的布局语义。

### 中文字体

字体保留 ASCII、高位西文、东亚和复杂文字四类字体及主题角色，不能用单一 CSS 字体列表掩盖中西文字体差异。东亚文字及全角标点按对应字体表达，中文扩展区字符不按 UTF-16 单元错误拆分。主题根据来源语言选择 Hans/Hant 等字体。预览不自动下载字体；缺失字体通过本地测量报告替代，保留源字体名称，并区分替代后的版式与原字体保真。固定视觉环境记录中文字体文件摘要，覆盖混排、字号、字重、行距、断行和表格溢出。

### 样式与编号

原生段落、字符、表格样式保存身份、类型、`basedOn`、关联与后续样式引用；其外观写入 CSS。导入按 OOXML 默认属性、主题、继承、条件样式和直接格式规则生成有效外观，循环或缺失的必要引用失败。源定义与导出关联保留；直接编辑先通过行内 CSS 覆盖。

编号模型保存抽象定义、实例、层级、格式、模板、起始值、覆盖及段落引用。HTML 列表保留内容结构；显示标记由编号语义派生，不能把编号文本重复写入正文。复杂或不支持的编号不静默降为普通数字。

### 链接、制表位和字段

书签以稳定节点引用表达。超链接保存目标或书签引用，不在读取时访问目标；预览默认不导航。制表位保存段落内位置、对齐及引导符，实际宽度由渲染器根据字体测量。

字段保存指令、结果内容根和缓存状态；结果的文字及样式位于 HTML。简单字段、复杂字段和嵌套字段使用相同语义。导入不执行字段指令、不访问外部数据；原缓存标为未重算。分页阶段负责页码、总页数及目录等支持的更新。

### 批注和修订

批注正文采用纯文本或富文本内容引用，两种来源互斥。富文本内容不再复制为另一份 `instruction`；请求中的可读指令由内容派生。保留来源 ID、作者、时间及跨节点锚点，初始 `baseRevision` 为 0。

文字修订使用插入/删除容器，保存来源修订 ID、作者和时间，保留被删除文字。Word 修订与 SDK 的 `revision` 是不同概念。读取时显示修订标记，不自动接受或拒绝。格式、移动和表格结构修订在首批读取中明确失败。

## PPT：定位对象

`Presentation → Slide → Shape` 为主要层级。演示文稿保存尺寸、幻灯片顺序、主题；幻灯片引用母版和布局并保存局部覆盖。对象使用有身份的 HTML/SVG 节点，包含文本框、图片、形状、连接线、表格、图表和组。

对象模型保存局部几何、变换、旋转、层级、裁剪及组合关系；组变换组合得到显示几何，拖拽后写回对象源。文本使用公共区块/行内模型并保留形状文本框的内边距、垂直对齐和自动适配语义。形状填充、轮廓、字体及主题颜色经样式引用解析。

主题、母版、布局与对象分别保存定义和引用，不复制为四份可独立编辑的对象。SVG/图像仅可用于明确声明的单对象视觉保留，文字和普通表格仍按原生对象导出。演讲者备注、动画、复杂图表等扩展按能力矩阵接入，不通过任意 JSON 字段绕过校验。

## Excel：分块工作簿

`Workbook → Sheet → Chunk → Cell` 为加载和索引结构。工作簿保存工作表顺序、名称及共享定义；工作表保存行列、合并、冻结、过滤、命名范围、条件格式、图表及对象引用。单元格由表身份及坐标稳定定位，分块只是加载边界，不改变单元格逻辑身份。

单元格内容区分空白、文本、布尔、数字、错误和公式。常量的类型和值是内容源；公式表达式是计算源，缓存值及其有效状态是派生数据。日期按数值、数字格式及日期系统共同解释，不能把显示字符串当作原始值。公式计算适配器不保存第二份可独立变化的工作簿。

外观以 CSS 和样式引用保存；原生数字格式、行高、列宽、隐藏、合并及条件规则保存格式语义。行列度量保留原生单位和所需字体条件。仅可视窗口产生 DOM，完整数据不展开为全量浏览器表格。跨表引用、相对/绝对地址、命名范围及公式错误由计算适配器处理；外部引用不自动发起网络读取。

## 接口、版本与验收

当前 `openDocument/snapshot/getNode/serialize` 已实现 Word 和 [R2-02 Presentation 文档包模型](presentation-model.md)，并保留 Word 旧包。PPTX 原生读取及 Excel 文档包读取仍未开放；模型实现不代表原生格式或预览验收已通过。结构类型来自严格契约及同源 JSON Schema，节点存在、引用、层级、锚点和样式循环另做语义校验。

格式仍为未发布的版本 1 草案。新增字段显式定义，旧报告包继续可读；发布冻结后保留已支持的读取器，不通过忽略未知字段兼容。Word 读取结果必须经过文档包校验，并满足保存、ZIP 打包及重开语义一致。三格式正式实现时分别使用真实格式文件验证原生语义与视觉，不能用模型设计代替实现验收。

## 类型与来源映射

以下是三格式运行时的设计类型，不是第三方 AST，也不是新的保存文件。当前 Word 和 R2-02 Presentation 契约由 `core` 的 Zod 定义推导；下列宽泛枚举还包含后续类型，不能据此推断实现范围。Excel 类型在第三轮落地，当前读取器仍拒绝 workbook。

```ts
type NodeId = string;
type StyleId = string;
type AssetPath = string;
type Pt = number;
type NodeRef = { nodeId: NodeId };
type NativeStyleRef = { styleId: StyleId };
type Point = { x: Pt; y: Pt }; // 允许负坐标
type Size = { width: Pt; height: Pt };
type Transform = Point & Size & {
  rotation: number;
  flipH: boolean;
  flipV: boolean;
};
type InlineKind = "text" | "break" | "image" | "link" | "field" | "tab" | "revision";
type BlockKind = "paragraph" | "heading" | "list" | "table";
type StoryKind = "main" | "header" | "footer" | "comment";
type ShapeKind = "text" | "image" | "geometry" | "connector" | "table" | "chart" | "group" | "visual";
type CellValueKind = "blank" | "text" | "number" | "boolean" | "error" | "formula";
```

| 运行时对象 | 唯一来源及关系 |
| --- | --- |
| Word 区块和行内对象 | HTML 节点及受支持语义属性；公共节点索引派生父子关系及 UTF-16 文字视图 |
| Word 内容域、节、样式图和编号 | 类型化元数据引用 HTML/CSS；节页设置覆盖文档默认页设置，缺省页眉页脚引用在导入时显式展开继承 |
| 字段 | 元数据保存指令及起止/结果节点引用；嵌套指令保存子字段引用及其插入偏移；缓存文字在 HTML 中只有一份 |
| 原生批注 | `annotations` 保存身份、范围和来源显示信息；正文为纯文本或 comment 内容域引用，两者互斥 |
| PPT 变换 | HTML 对象的类型化 `data-office-*` 几何属性是原始值；定位 CSS 和父子合成矩阵由其派生 |
| PPT 样式 | CSS 保存外观，元数据保存主题/母版/布局及局部覆盖引用；原生对象和视觉保留对象分开声明 |
| Excel 值 | 文本来自 HTML；数字/布尔/错误由类型及原始值属性定义，格式化文本是缓存；公式由公式属性定义 |
| Excel 结构 | 元数据保存行列度量、合并、冻结、共享样式、名称和规则；跨块索引按工作表与坐标唯一定位 |
| 图表 | 元数据保存类型及数据引用或唯一的内嵌数据；SVG/画布只是显示结果；不重复保存可独立修改的数据表 |

### PPT 元数据设计示例

下面的 JSON 是 R2-02 已接受的元数据结构示例；完整可校验文档包见 [Presentation 样例](../examples/presentation/README.md)。对象几何位于 HTML 属性，不在元数据再存一份；该示例不表示原生 PPTX 读取已实现。

```json
{
  "presentation": {
    "size": { "unit": "pt", "width": 960, "height": 540 },
    "commentFormat": "modern",
    "slides": [{ "slideId": "slide-1", "rootNodeId": "slide-root-1", "layoutId": "layout-1" }],
    "themes": [{ "themeId": "theme-1", "cssClass": "theme-1" }],
    "masters": [{ "masterId": "master-1", "rootNodeId": "master-root-1", "themeId": "theme-1" }],
    "layouts": [{ "layoutId": "layout-1", "rootNodeId": "layout-root-1", "masterId": "master-1" }],
    "notesMasters": [],
    "stories": [],
    "objects": [{ "nodeId": "title-1", "kind": "text", "placeholder": { "type": "title", "index": 0 } }],
    "charts": [],
    "dataSets": [],
    "comments": [],
    "hyperlinks": []
  }
}
```

对应正文包含 `section[data-node-id=slide-root-1]` 和 `div[data-node-id=title-1]`。标题对象保存 `data-office-x/y/width/height/rotation`；显示时换算缩放，导出时换算 EMU。母版、布局有独立内容根，预览根据引用组合，不复制到幻灯片正文。组还保存原生子坐标原点与范围，子对象变换不受屏幕缩放影响。

### Excel 元数据设计示例

下面的 JSON 是第三轮的目标结构示例，当前读取器不接受。行列窗口由分块清单定位；一个合并区域可以跨窗口，但只有一个逻辑定义。

```json
{
  "workbook": {
    "dateSystem": "1900",
    "sheets": [{ "sheetId": "sheet-1", "name": "预算", "rootNodeId": "sheet-root-1" }],
    "dimensions": [{ "sheetId": "sheet-1", "rows": [{ "index": 1, "heightPt": 24 }], "columns": [{ "index": 1, "width": 12, "unit": "characters" }] }],
    "merges": [{ "sheetId": "sheet-1", "from": "A1", "to": "B1" }],
    "frozen": [{ "sheetId": "sheet-1", "rows": 1, "columns": 0 }],
    "numberFormats": [{ "formatId": "money", "code": "#,##0.00" }],
    "names": [],
    "conditionalFormats": [],
    "charts": []
  }
}
```

单元格 `A2` 的数字以 `data-value-type=number` 和原始值属性保存，展示文本由 `formatId` 派生；文本单元格的 HTML 是文本来源。公式单元格保存表达式、原缓存类型和值及 `valid/stale/unavailable` 状态，修改依赖后不能继续将旧缓存标为有效。日期系统、数字格式、公式缓存和实际计算分别解释，不相互替代。

### 引用与变更规则

- 样式、内容域、母版、布局、表、对象、单元格及资源引用必须存在并匹配类型；继承图及嵌套字段不得循环。
- 节属于正文域；批注正文、页眉页脚不混入正文编辑范围。跨域范围必须明确拒绝，不能按临近节点猜测。
- PPT 父子关系是树；几何更新只写原始变换属性。Excel 分块不得导致重复单元格身份，合并与规则引用按逻辑坐标校验。
- 区块替换、对象移动、单元格写入及批注变更后，都重新校验受影响引用，并经同一事务批量提交；自动分页、选区和缓存重建不独立推进修订。
- 新格式专属操作在实现时显式加入契约，模型设计中的类型名称不会自动成为当前已支持操作。
