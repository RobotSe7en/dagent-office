## 目标与已定决策

交付新建或打开 XLSX、人工编辑、区域批注、宿主请求、固定提案审阅应用、撤销重做、XLSX/PDF/PNG/文档包导出，以及外部实际修改后的重新导入。

- 第三轮覆盖常用办公闭环，包括原生智能表、基础条件格式、数据验证、三类图表、图片、基础形状和文本框。
- XLSX OOXML 读写、公式解析、引用重写、依赖图、求值和虚拟网格均由本项目实现。不采用 Univer 或其他第三方公式引擎、表格编辑器及 Office 转换库；通用 ZIP/XML/HTML/CSS/哈希原语继续复用。
- 按用户最新决定，验证基线为单表 1 万行 × 20 列、20 万实际单元格、约 2 万公式，另覆盖多表依赖和稀疏远端坐标。必须使用实际数据验证；十万行不再作为本轮验收门槛。
- 经典备注、现代线程均进入导入、编辑和导出范围。SDK 多区域锚点在排序时跟随数据，区域拆散后精确保留为多个范围；目标删除才要求重新定位。
- 输入保守识别：明确数字、布尔及以 `=` 开头的公式自动识别；前导零、超长编号和歧义日期保留文本。提供显式转换及文本输入。
- 能安全解析、保留和维护引用但尚不能求值的普通公式允许导入。来源缓存、当前计算结果、过期与不可计算分别表示；不能用旧值冒充新结果。无法可靠解释的语法明确拒绝。
- 人工输入、粘贴、填充和提案统一执行数据验证。停止型违规整批失败；警告型进入候选诊断及确认；导入已有违规值保留并报告。
- 多单元格批注导出到代表单元格并附范围说明，报告定位损失；文档包保留完整锚点。代表单元格冲突的项明确报告未导出，不覆盖或自动合并线程。
- PDF/PNG 默认要求结果有效；允许用户显式选择缓存快照，但页面与报告都标识未重算结果。
- 所有阶段 PR 由实施者提交、推送、独立审查、修复复核，并在最终提交全部 CI 通过后合并。这是用户在实施开始后更新的授权，替代此前人工合并安排。不直接提交 main、不发布 npm、不使用子代理。

## 自研公式范围与语义

| 类别 | 必须验收的函数 |
| --- | --- |
| 聚合与条件统计 | SUM、AVERAGE、MIN、MAX、COUNT、COUNTA、COUNTBLANK、SUMIF、SUMIFS、COUNTIF、COUNTIFS、AVERAGEIF、AVERAGEIFS、SUBTOTAL |
| 逻辑与类型 | IF、IFS、IFERROR、IFNA、AND、OR、NOT、TRUE、FALSE、ISBLANK、ISNUMBER、ISTEXT、ISERROR、ISNA |
| 数值 | ABS、INT、TRUNC、MOD、ROUND、ROUNDUP、ROUNDDOWN、POWER、SQRT |
| 文本 | LEN、LEFT、RIGHT、MID、TRIM、UPPER、LOWER、CONCAT、CONCATENATE、TEXTJOIN、SUBSTITUTE、REPLACE、FIND、SEARCH、EXACT、TEXT、VALUE |
| 日期时间 | DATE、YEAR、MONTH、DAY、TIME、HOUR、MINUTE、SECOND、DAYS、EDATE、EOMONTH、WEEKDAY、TODAY、NOW |
| 查找地址 | VLOOKUP、HLOOKUP、INDEX、MATCH、ROW、COLUMN、ROWS、COLUMNS |

支持算术、比较、连接、百分号、错误传播、条件短路、相对/绝对/混合引用、跨表、普通区域、整行整列聚合及智能表常用结构化引用。共享公式按来源基准映射为等价表达。不能把解析成功记为计算正确；参数转换、空白与空字符串、日期、错误、通配符、查找模式和过滤后的 SUBTOTAL 分别验收。

公式语法树、依赖图和缓存均为派生状态。区域依赖不展开为百万条单元格边；同模板公式共享解析结构。计算结果绑定文档、修订、批次和引擎版本；迟到结果拒绝，不新增历史步骤。源编辑立即使依赖结果失效；停止型验证需要的计算在候选通过前完成，其余结果可以后台更新。

TODAY/NOW 在同批使用一致的时间上下文。宿主适配器提供时间，核心不直接读取系统时钟。新建默认自动计算，导入保留来源计算模式，提供手动重算。支持 1900/1904 日期系统及历史序列边界。合法的公式错误结果与引擎尚不能求值分别表示。

复制公式调整相对引用；剪切移动、行列插删、工作表/表格/列改名采用各自的引用映射，不做字符串替换。排序先冻结键，稳定排序后重算；批注跟随数据。用户已明确：排序区域外的公式继续引用原地址，不跟随被排序记录；例如原 B2 记录移到 B8，区域外 `=B2` 仍为 `=B2`。区域内公式随记录搬移并按相对/绝对引用规则调整。条件格式、验证和图表同样引用当前计算状态。

用户也已明确剪切语义：引用跟随被剪切的数据。将 A3 剪切到 C3 后，`SUM(A1:A5)` 精确改写为等价的多区域引用 `SUM((A1:A2,A4:A5,C3))`；不以原矩形或包含额外单元格的包围框代替。拆分后的引用仍受公式长度和节点预算约束。

## 数据、模块与接口

### 分块来源

继续使用 core/render/editor/office/node 五包。工作簿以 256 行 × 32 列逻辑窗口组织分块 HTML，只保存实际内容及必要格式。分块索引记录表身份、窗口、路径及摘要；合并、规则和对象引用在元数据只有一份定义。空白远端坐标不生成全量节点。

Word/PPT 单入口包继续可读；工作簿使用明确的 chunks 分支。工作簿快照不拼接全表 HTML、不展开完整节点列表。完整检查包、块及引用，逐块解析并释放临时树，常驻状态为紧凑索引和有界缓存。来源单元格身份不取决于虚拟窗口；坐标变化通过范围映射表示。

事务、候选和历史共享不可变块；小编辑只复制受影响块。公共事务生命周期与格式适配分离，不另设工作簿历史。序列化可以接收同修订的计算结果，把派生缓存写入输出包；不原地重写旧修订。

### 浏览器执行

浏览器默认在宿主创建的 Worker 内持有唯一工作簿会话。SDK 提供传输适配，Worker 仍调用同一核心事务；主线程只持有元数据、窗口、差异和状态。Playground 提供宿主 Worker 入口；Node 和小型嵌入保留直接核心调用。

导入、批量操作、排序、重算和导出支持进度、取消及修订守卫。冻结窗格、主体及对象层共用坐标系统；逻辑滚动避免浏览器元素高度上限。DOM 虚拟化不改变复制结果、地址或批注定位。

### 编辑与协作细则

- 单元格操作在候选最终状态校验引用和受影响规则，后续失败不留下前序修改。
- 合并覆盖非空内容必须由用户明确选择处理方式；非法跨合并粘贴、排序或结构操作整批拒绝。
- 智能表计算列的实际单元格公式是内容源，自动填充通过事务完成；表样式用共享引用，不展开为全表重复格式。
- 图表引用当前单元格/名称，不维护独立可写数据表；原生缓存由当前结果生成。
- 请求包含预算内可写上下文与只读依赖。结构修改引起的公式重写也是写入，越界必须要求更大作用域，不能自动扩权。
- 只读依赖的派生重算可产生影响，须与直接源修改区分。大表不默认发送完整工作簿，不截断上下文后继续应用。
- 差异覆盖值、公式、格式、结构、规则、绘图和批注锚点，候选应用后才变更当前源。

## 验收与资源目标

### 独立样例

源 XLSX 使用 Python 标准 ZIP/XML 自行生成，不使用本项目导出器或第三方 Office 转换库。独立内容预期、源摘要、Calc 重存、固定字体 PDF/PNG、工具版本及字体摘要一起记录。至少覆盖类型和富文本、日期/数字格式、主题样式、行列冻结合并、跨表/名称/共享公式、智能表、排序筛选、条件格式、验证、三类图表、图片、形状文本框、经典备注、现代线程、打印、多表组合、一万行实值和非法/超限输入。

外部自动验收沿用官方归档和 SHA-256 固定的 LibreOffice 25.8.1.1。分别检查规范、SDK 精确重开与外部应用；现代线程在外部丢失时单列，不能冒充无损成功。Excel/WPS 未实机验证时明确记录。

### 性能基准

这些数值是目标，不是当前能力承诺。固定 4 vCPU、8 GiB、浏览器和字体，记录基准生成器及哈希。

| 指标 | 验收目标 |
| --- | --- |
| 主数据 | 1 万行 × 20 列、20 万实际单元格、2 万公式 |
| 补充 | 多表查找聚合、长链、高扇出、稀疏远端、排序及表扩展 |
| 打开 | XLSX 至可交互首屏不超过 30 秒，主线程可响应且可取消 |
| 全量计算 | 固定主基准公式负载不超过 15 秒 |
| 普通编辑 | 影响不超过 1000 个公式时，提交至结果更新 p95 不超过 500 毫秒 |
| 交互反馈 | p95 不超过 100 毫秒，计算不长时间阻塞主线程 |
| DOM | 1280 × 800 下所有窗格单元格元素合计不超过 5000，不随总数据量增加 |
| 内存 | 浏览器及 Worker 增量峰值不超过 2 GiB；100 次小编辑历史不按整本大小增长 |
| 批量操作 | 一万行排序、批量修改和重算可观察进度、可取消，取消无部分提交 |

显式大工作簿配置：压缩输入 128 MiB、累计展开及源包各 512 MiB、源块 8 MiB、最多 250 万实际单元格、25 万公式。原生大型工作表 XML 流式处理，单部件最高 256 MiB，仍受累计预算约束。候选与历史按唯一保留块计量，各 512 MiB，历史最多 100 步。分配前检查字节、节点、公式、依赖、计算步骤与输出限额；拆块或嵌套包不得重置预算。

上述额度是资源保护上限，不代表已经验证的支持容量；本轮容量验收仍以一万行为准。该配置不扩大旧 Word/PPT 默认额度。历史或候选超限明确失败，不暗中删历史。打印保留页数、节点、像素和字节上限；过大的全表打印在生成前失败，可选择更小打印区域。

### 检查矩阵与命令

验证严格契约和同源 Schema、跨块引用及安全输入、公式类型和错误语义、原子事务和映射、真实 IME、三引擎和旧 Chromium/Safari、两类批注、提案作用域、打印、Worker/资源/子进程释放及独立打包。范围限额和性能目标分别验证。

已提供 `fixtures:xlsx`、`check:xlsx-fixtures`、`check:xlsx-reference` 和单独的 `record:xlsx-reference`。计划新增 `check:workbook-calculation`、`check:workbook-performance`、`check:xlsx-export`、`check:workbook-closure`；后四项尚未实现，落地后才记录结果。普通检查不改参考基线。

原生链路必须包含独立来源导入、当前源修改、导出、结构检查、Calc 实际修改值/公式/表格/图表/备注后重存、SDK 重新导入。独立打包在工作区外安装五个 tarball，普通 JS 不安装 React，不使用源码私有路径。每阶段保留 Word/PPT 回归。

## 阶段交付

五个 PR：工作台收尾；路线同步与 R3-01；R3-02～08 读取；R3-09～16 编辑计算；R3-17～20 输出及验收。每阶段先做窄范围验证，再对提交差异独立审查、修复复核，最终提交全部 CI 成功后合并。用户已授权实施者合并全部阶段；不再等待人工合并。后续以最新 main 为基线，不直接向 main 提交。

性能或兼容性未达标先修实现；缩减已选范围、降低一万行目标或改变产品语义须重新询问用户。当前阶段完成不意味着后续阶段、R1 宿主验收或 0.1 发布门槛已通过。

## 规范依据

- [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/)：SpreadsheetML、DrawingML、OPC。
- [MS-XLSX 公式](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/3d025add-118d-4413-9856-ab65712ec1b0)：公式扩展及语法。
- [智能表结构化引用](https://support.microsoft.com/en-gb/excel/using-structured-references-with-excel-tables)：表名、列名、计算列及汇总行。
- [现代线程批注](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/e0fb917a-1107-409a-852f-13b47aea70dc)：单元格线程、回复和来源作者。
- [日期系统](https://support.microsoft.com/en-us/excel/date-systems-in-excel)：1900/1904 日期语义。

以上规范用于本项目自行实现，不引入 Microsoft Open XML SDK 作为运行时转换依赖。
