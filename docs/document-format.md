# HTML 文档格式

`DocumentPackage` 是 dagent-office 的持久化文档源。它由规范 HTML、CSS、格式元数据、资源和批注组成，可以保存为目录或 ZIP。原始 Office 文件是可选的来源材料，文档包能够独立编辑和导出。

本格式处于设计阶段。首次发布冻结版本 1 后，外部文档继续由显式的版本读取器导入；未知版本返回类型明确的错误，不能按字段形状猜测版本。

R1-03 已实现清单、Word 基本元数据及批注的[结构校验](contracts.md)；R1-04 已实现单 HTML 入口的[包读取、HTML/CSS 解析、节点索引、元数据引用及保存重开](document-model.md)。图片格式与摘要、完整资源及 ZIP 在 R1-05 实现。当前所有协议对象严格拒绝未知字段；分块及更丰富的格式元数据在后续任务显式加入，不通过额外字段隐式接收。

## 包结构

```text
manifest.json
content.html                 小文档的正文入口
content/                     大文档使用的分块入口，与 content.html 二选一
styles.css
metadata.json
annotations.json
assets/
```

`manifest.json` 包含：

| 字段 | 含义 |
| --- | --- |
| `format` | 固定为 `dagent-office` |
| `formatVersion` | 持久化格式版本，设计值为 `1` |
| `documentId` | 不透明文档 ID，不授予访问权限 |
| `kind` | `document`、`presentation` 或 `workbook` |
| `revision` | 当前文档版本，从 `0` 开始，每次成功修改加一 |
| `entrypoint` | 单文件 HTML 入口；分块形式使用 `chunks` 索引替代 |
| `styles` | 按顺序加载的包内样式路径 |
| `metadata` | 格式元数据路径 |
| `annotations` | 批注路径 |
| `assets` | 资源描述，包含包内路径、MIME 类型及 SHA-256 |

包内路径必须为安全相对路径。读取器限制包大小、解压大小和节点数量，拒绝重复路径及越界路径。资源可以由宿主授权存储提供，正式打包为可移植 ZIP 时应完整收集。

资源描述的字段为 `path`、`mimeType` 和 `sha256`，后者使用 64 个小写十六进制字符。当前只验证字段和摘要字符串形状，真实字节、资源格式、授权与摘要匹配由后续读取层验证。

## HTML 约定

采用办公文档使用的 HTML 结构：段落、标题、列表、文字片段、表格、图片、链接、章节、幻灯片、形状和图表容器。通过扩展节点定义 SVG、图表和公式等语义。

每个可定位节点有唯一 `data-node-id`。新建节点由核心分配 ID；移动节点保留 ID；复制节点取得新 ID。文字片段的选区使用节点内偏移，不能以 DOM 路径或屏幕坐标作为唯一地址。

```html
<article data-node-id="root" data-office-kind="document">
  <h1 data-node-id="n-title">项目实施报告</h1>
  <p data-node-id="n-summary">项目计划于第三季度完成。</p>
</article>
```

HTML 的解析与序列化保留受支持节点和扩展属性。模型提供的新 HTML 经过同样的解析器进入文档核心。脚本、事件处理器、可执行嵌入和未经授权的外部资源地址不属于该格式。

首批支持结构和属性见[第一轮实施细则](iteration-1.md)。读取已有包检查必要节点身份；格式导入和新片段生成节点时由核心规则分配身份。对不支持的结构返回明确结果，不能静默丢弃后保存。

## 保真目标

文档格式与适配器以保真为目标：导入和预览应尽可能还原原文档的字体、颜色、段落、表格、图片、页面设置和分页布局；局部编辑、保存重开和导出应保留未修改部分的内容及样式。当前 HTML/CSS 支持表是阶段性实现范围，后续应按原文档的保真需求扩展，不作为格式的永久上限。

安全校验与样式能力分别定义。脚本、事件处理器、可执行嵌入及未授权资源访问必须拒绝；普通选择器、排版属性或字体能力尚未实现，不等同于存在安全风险。资源仍须经宿主授权并符合包内引用规则。

后续实现应分别声明源样式保留、预览、编辑和导出能力；编辑器缺少某个格式命令，不应导致安全且可表达的源样式被删除。无法表达或还原的特性必须明确报告，不能静默删除、重置为默认样式或以整页图片代替可编辑内容。保真验收固定字体和渲染环境，导入对照原文档，导出对照修改后的文档，并覆盖未修改部分的样式保留。当前已实现范围见[文档模型](document-model.md#htmlcss-支持范围)，不代表已完成 Office 视觉保真验收。

## 样式和资源

CSS 保存文字、段落、表格和对象的外观。支持的样式属性以编辑和导出适配器的能力表声明。几何值转换到统一的逻辑坐标；页面外框、缩放、光标和批注高亮等编辑器样式不保存到文档源。

文档级页面设置、原生引用等由 `metadata.json` 保存。相同含义的值只指定一个来源：例如页面宽高以元数据为准，预览页容器的 CSS 是由它生成的派生值；文字颜色以文档 CSS 为准，不在元数据另存一份可独立修改的颜色。

当前基本元数据要求 `pageSetup` 和至少一个 `sections` 引用；`title` 和 `locale` 可省略，校验器不填默认值。编号、复杂样式关联、页眉页脚等计划在 DOCX 映射任务中显式补齐结构。

首轮 `setStyle` 修改目标节点的行内 CSS 声明，原有样式表按既定顺序继续参与级联；行内声明与外部样式共同属于文档源。CSS 变量和继承保留语义，显示及导出所需的有效样式由渲染适配器计算，核心不保存另一份可独立编辑的计算样式。

图片等资源由包内相对路径引用。资源内容保持不可变，替换资源时创建新资源描述并更新节点引用。字体和渲染器版本进入视觉基线环境，字体文件的分发范围按其许可确定。

## Word 文档

正文是连续的内容流，分页容器由布局层计算。明确的分页和分节作为节点或语义属性保存，自动换页结果不切断正文源。

元数据保存页面大小、页边距、节与页眉页脚引用、编号定义和导出所需的样式关联。表格保留行列、合并、边框和嵌套内容。图片保留尺寸、裁剪及环绕语义。

对 Word 编号、样式继承和域分别建立导入映射。页码和目录等动态字段保存字段语义，其可见文本是派生结果。

## PPT 演示文稿

每张幻灯片是固定尺寸的 `section`，对象具有节点 ID、类型、层级和逻辑几何。位置、尺寸、旋转和层叠顺序由对象样式或专用属性保存，编辑器缩放不改变这些值。

母版和主题存于元数据，对象保存引用及明确覆盖项；导入器计算预览所需的有效样式。文本、表格、图片和形状分别导出为可编辑对象。复杂装饰可表示为独立 SVG 或图片对象，并记录其编辑能力。

## Excel 工作簿

工作表以分块 HTML 表格表达，单元格节点携带工作表和地址信息。只加载可视窗口所需的行列，不把完整工作簿展开为一个 DOM。

```html
<td data-node-id="cell-total" data-sheet-id="sheet-1"
    data-cell="C8" data-value-type="number"
    data-formula="=SUM(C2:C7)">12800</td>
```

常量单元格的原始值和类型是内容源；公式单元格的公式是计算源，展示文本及公式缓存结果是派生值。编辑后的计算结果由公式适配器产生。无法计算时保留公式并标明结果未更新，不伪造新结果。

元数据保存工作表次序、行列尺寸、冻结、合并、命名范围、图表及对象引用。单元格的内容不另存一套可以独立变化的工作簿 JSON；接入计算器或网格组件时，其内部数据是从文档源构建的运行时表示。

## 分块和版本

分块索引描述每块的路径、节点范围和顺序。Word 按连续内容区块、PPT 按幻灯片、Excel 按行列窗口分块。一个逻辑表格或区域跨块时保留稳定的逻辑 ID。

`formatVersion` 表示格式契约，`revision` 表示内容变更，两者不能混用。修订产生新快照或增量记录，既有历史快照保持不可变。宿主决定历史保留期限，SDK 提供读取、序列化和显式升级能力。

内容和批注的有效事务均推进当前修订；临时选择、缩放、生成交互请求及预览候选不推进修订。撤销重做恢复内容但仍产生新的修订号，避免错误接受旧提案。

导入兼容性记录指出哪些对象可编辑、哪些按视觉对象保留、哪些转换无法完成。它属于文档的能力说明，不等同于用户授权。

## 批注与派生交互数据

`annotations.json` 保存批注 ID、所属文档、基准修订、锚点、说明和状态。文字锚点使用节点内 UTF-16 范围；跨节点文字保存有序范围；区域锚点保存逻辑渲染面、pt 矩形、命中节点和布局标记。分页视图的页面是派生结果，不能把自动分页容器当作持久化正文。详细映射和失效规则见[编辑与宿主交互协议](editing-protocol.md)。

交互请求和修改提案是基准修订的派生任务数据。宿主可以将它们保存为附件或产物，但它们不成为另一份当前文档源，也不作为正文入口写入 manifest。请求中的 HTML 区块是完整子树快照，提案只通过核心事务更新当前包。

请求 ID 用于关联宿主任务和返回提案；文档修订用于冲突检查，宿主存储版本用于正式提交比较。三者不能相互替代，也不授予访问权限。

## 示例

完整目录见 [examples/report](../examples/report/)。该示例使用单文件正文、无外部资源和两条初始批注，初始修订为 0；[report.request.json](../examples/report.request.json)冻结对应批注、正文、样式和元数据，[report.proposal.json](../examples/report.proposal.json)关联同一请求并修改正文及标题颜色。

运行时如果新建批注或人工编辑，须使用变更后的当前修订重新生成请求。示例中的 0 只属于该初始包，不能作为交互中的固定修订。
